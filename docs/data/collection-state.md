# 图鉴状态数据库

## 数据库

| 属性 | 值 |
|---|---|
| 名称 | `xiv-companion-collection-state` |
| 版本 | `3` |
| 实现 | `src/app/collection_state.rs` |

该数据库只保存用户主动标记为已获得的 Item ID，与图鉴目录、分类和版本数据分离。

## `collections`

每个已获得物品对应一条 record，使用 out-of-line key。

### Key

Item 表的 `u32` Row ID，以十进制字符串保存：

```text
12345
33041
45678
```

分类不属于持久化 key。同一个物品在分类规则调整后仍使用相同的获得状态。

### Value

```ts
true
```

Value 是占位值。record 存在表示已获得；未获得不保存 record，取消获得时直接删除对应 key。因此该 store 在逻辑上是一个稀疏的 `Set<ItemId>`。

### 读写方式

- 页面启动：一次 `getAllKeys()`，在内存中构造 `HashSet<u32>`。
- 页面查询：只查询内存 Set，不逐项访问 IndexedDB。
- 单项勾选：`put(itemId, true)`。
- 单项取消：`delete(itemId)`。
- JSON 导入：在一个读写事务中执行 `clear()` 和逐项 `put()`。
- 装备同步：根据物品快照重新计算装备部分，新增和不再持有的装备都会进入确认预览；解锁类状态不受影响。

数据库从 v2 升级到 v3 时，会将 `entries` 中的 `{collection-kind}:{item-id}` key 转换为纯 Item ID，然后删除 `entries`。旧 `state` store 不再参与兼容读取，会在升级时删除。

## 导入导出

JSON 格式带独立 schema 版本：

```json
{
  "schemaVersion": 1,
  "items": [12345, 33041, 45678]
}
```

导出时 Item ID 按数字升序排列。导入会校验 schema 版本和 Item ID，并自动去重；导入是整体替换，不与现有状态合并。

## 内存表示

```rust
HashSet<u32>
```

图鉴目录定义当前可展示的物品，用户 Set 可以保留暂时不在当前目录中的 ID，避免目录或分类变化丢失用户状态。

## 图鉴分区

图鉴页分为两个顶层分区：

- **装备**：`CollectionKind::Equipment`，状态来自角色已知物品容器快照，可以按职业、部位和版本查看。职业筛选可选择全部、三种职业大类或一个具体职业；部位筛选不单列复合部位，默认全部时仍会显示这些装备。
- **解锁**：除装备外的永久解锁类条目，例如坐骑、宠物、乐谱、情感动作、发型与面妆、生产秘籍和九宫幻卡等。

两类状态仍共用 Item ID 集合，但同步语义不同。装备同步不会修改解锁类条目。

## 从物品数据同步装备

图鉴页不再为持有型条目建立单独的 WebSocket 同步连接。“同步装备状态”读取物品页保存在 IndexedDB 中的最新完整快照：

- 当前只处理 `CollectionKind::Equipment`，即装备 Tab 的持有型图鉴条目。
- 合并所有已保存容器快照中的基础 Item ID，再与装备图鉴目录取交集。
- `live` 和 `cached` 中存在物品都可以作为正向证据；所有已知快照都不再包含的装备会被视为不再持有。
- `notLoaded` 容器会保留其上次持久化的正向记录，不会因为暂时没有可报告内容而删除装备。
- 永久解锁类条目不会被该操作修改，后续由独立的 UnlockService/API Bridge 同步流程负责。
- 结果先与当前浏览器图鉴比较，显示新增和移除预览；用户点击“确定”后整体替换装备部分，取消不会修改任何记录。

物品快照不存在时按钮禁用，并提示先前往物品页执行全量刷新。图鉴同步按钮本身不访问 bridge。

### 角色作用域边界

当前数据库仍是浏览器级全局 Item ID 集合，没有按游戏角色分区。切换角色后，桥接同步会把多个角色观察到的状态合并为并集。这适合账号级总览，但不能表达单角色完成度，尤其会混合装备持有状态。

在改为按角色存储前，需要先完成以下协议和迁移设计：

- 桥接提供不含角色名、可稳定区分本机角色的作用域 ID，并支持连接后主动查询当前作用域。
- IndexedDB key 增加角色作用域，同时保留独立的账号总览或并集视图。
- 现有无作用域记录不能静默归入当前角色；升级时应保留为 `legacy/global`，由用户选择继续作为总览或合并到指定角色。
- 登出和切换角色必须使当前连接的同步结果失效，前端收到新作用域后再加载对应状态。

在上述边界落地前，不向现有 v3 数据库加入推测性的角色 key。
